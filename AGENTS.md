# Работа с QA-проектом

- Отвечай по-русски. Сохраняй реальные имена файлов, команд и API.
- Сначала прочитай [профиль проекта](docs/coverage-profile.md). Языки продукта и тестов выбирает учащийся; не определяй их по названию курса или примеру из другого проекта.
- Пути, стек и доступ к каждому виду тестов бери из профиля. Команды и соглашения — из README и конфигурации соответствующего модуля. При расхождении покажи его; не подставляй знакомую команду.
- Требования бери из задания и относящихся к нему контрактов. Существующая реализация показывает поведение, но сама по себе не доказывает, что оно правильное.
- Выполняй согласованный объём работы. Для запроса на анализ не меняй код. Не исправляй тест или селектор до диагностики и разрешения пользователя; явная просьба исправить уже является разрешением в её пределах.
- Не выполняй commit, push, разрушительные git-команды, публикацию или действия на внешних стендах без соответствующей просьбы. Не выводи секреты. Не удаляй прежние результаты тестов без разрешения.
- Для тестов против стенда используй конфигурацию модуля. Проверяй допустимость операций и тестовых данных для выбранного стенда. Unit/component-тестам удалённый стенд может не требоваться.
- Не выдавай найденный тест за выполненный, пропуск или кешированный результат — за новое выполнение, а созданный ручной чеклист — за ручную проверку.
- Подтверждай выводы файлами, командами и результатами. Отделяй факты от гипотез. Отсутствие подтверждённых проблем — допустимый результат.

## Процедуры

Читай подходящий skill, затем только материалы, необходимые для задачи:

- [qa-run-tests](.agents/skills/qa-run-tests/SKILL.md) — выполнить выбранные тесты и проверить результат запуска.
- [qa-debug-test](.agents/skills/qa-debug-test/SKILL.md) — исследовать падение или нестабильность.
- [qa-write-test](.agents/skills/qa-write-test/SKILL.md) — добавить проверку согласованного поведения.
- [qa-coverage-audit](.agents/skills/qa-coverage-audit/SKILL.md) — сопоставить требования с проверками и составить план покрытия.

Выбор уровня проверки и смысл покрытия описаны в [testing.md](docs/qa/testing.md).
Подключение и проверка самого harness — в [harness-checks.md](docs/qa/harness-checks.md).
