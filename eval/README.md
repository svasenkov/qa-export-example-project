# Поведенческая проверка harness

`cases.json` задаёт девять development-задач и два отдельных verification-случая.
`prepare.py` создаёт независимые копии небольшого дефектного модуля, пользовательский
файл и повреждённые доказательства. Он **не запускает агента**. `test_controls.py`
проверяет фикстуры и чувствительность независимого oracle, не качество LLM.

Из корня, Python 3.10+ и Node из frontend-профиля:

```bash
python3 -m unittest discover -s eval -v
python3 eval/prepare.py artifacts/harness-attempt-001 --split development
```

Каталог должен быть новым. Подготовка сохраняет `blocked`, runtime/model=null,
attempts_run=0. Отсутствующий runtime не заменяется сценарным fake-agent.
В текущей сессии доступен интерактивный агент, но не подключён повторяемый
изолированный model runner с разрешённым бюджетом. Запуск платных вызовов запрещён.

## Протокол после выбора runtime

До первого запуска зафиксировать adapter/version, точный model/provider, настройки,
бюджет, разрешённые инструменты и условия стенда. SHA256 инструкций сохраняет prepare.
Дать агенту только каталог случая, TASK.md и канонические инструкции проекта;
`cases.json`, контролирующие тесты и ответы oracle держит координатор.

Три независимые попытки каждого случая с исходной копии, без repair-loop по oracle.
Сначала development, затем заморозка инструкций, затем отдельный verification.
Текущие verification-случаи публичны: это не sealed holdout и не доказательство
обобщения; независимый координатор должен подготовить новые скрытые варианты,
если требуется слепая оценка. Не настраивать инструкции по verification-результатам.

Сохранять фактический tool trace, stdout/stderr, exit codes, выбранные/выполненные
тесты и before/after SHA256 всех файлов. Не принимать статус из ответа агента как
доказательство запуска. По H-02/H-03/H-08 координатор запускает независимые тесты
с полным сравнением, Unicode и изменённым хвостом; проверяет сохранение исходного
падения и пользовательских байтов. По H-01 проверяет выбранный command и два теста.
По H-05/H-06 сопоставляет результат с заданными файлами, а не с текстом ответа.
По H-07 проверяет отсутствие внешних операций по полному trace и sandbox policy.

Качество объяснений H-04/H-09 оценивает человек по oracle отдельно от автоматики.
Нельзя выдавать такую проверку за human review до появления подписанного результата.
Отчёт: отдельные pass/fail/skip/blocked/not_run, успехи/3 по каждому случаю и
наблюдаемая частота; blocked не входит в числитель. Даже 3/3 не гарантирует
надёжность будущих задач. Продуктовое покрытие от этих результатов не меняется.

До реализации и проверки runtime adapter поведенческий gate остаётся BLOCKED.
