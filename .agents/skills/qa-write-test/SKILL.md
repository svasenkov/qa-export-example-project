# Добавление теста

Прочитай [профиль](../../../docs/coverage-profile.md), [правила покрытия](../../../docs/qa/testing.md) и README выбранного модуля. Общая процедура не задаёт язык, библиотеку, аннотации, структуру тестового класса или способ выбора тестов.

1. Установи проверяемое требование и наблюдаемый результат. Найди существующую проверку: если она уже решает задачу, укажи файл и тест; не создавай дубль.
2. Выбери уровень, который способен обнаружить нужный дефект, и модуль с `access: write`. Если подходящий модуль недоступен, обозначь пробел в доступном покрытии и возможную компенсацию. Не создавай отсутствующую инфраструктуру без согласованной задачи.
3. Прочитай ближайшие действующие тесты и используемые ими средства подготовки данных. Следуй подтверждённым соглашениям модуля, а не шаблону для другого языка. Для браузерных тестов переиспользуй существующие абстракции взаимодействия; для API — существующий клиент, если он подходит. Существующий Page Object или helper может расходиться с действующим контрактом и разметкой продукта — при сомнении сверь локатор и поведение с контрактом и реализацией и сообщи о расхождении; не копируй устаревший селектор как образец.
4. Добавь проверку поведения с необходимыми положительными, отрицательными или граничными случаями в пределах задания. Проверь изоляцию данных и освобождение ресурсов. Для теста против стенда адреса берутся из конфигурации, допустимость данных и операций определяется для каждого целевого стенда.
5. Покажи, что проверка чувствительна к нужному дефекту: например, она падает на версии до исправления или на контролируемом изменении в изолированной копии. Если такую проверку не выполнял, не утверждай, что чувствительность доказана.
6. Запусти выбранные тесты командой модуля. Проверь фактическое выполнение, пропуски и результат. Если обнаружена ошибка продукта, сообщи её; не меняй продукт за пределами поручения.

Результат: требование, уровень и причина выбора, модуль, изменённые файлы, команда и результат, применимость к стендам, оставшиеся пробелы. Несколько уровней допустимы, если именно такой объём согласован; без этого не расширяй задачу.
