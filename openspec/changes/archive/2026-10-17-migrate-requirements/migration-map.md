# Карта переноса исходного описания

Источник: `login-flow` v0.9. Это карта миграции, а не второй источник требований
и не результат проверки поведения продукта. ID относятся к `openspec/specs/`.

## Все 16 исходных acceptance-пунктов

1. Открытие формы входа → AUTH-001a.
2. Пустой логин → FORM-001a, FORM-001b.
3. Пустой пароль → FORM-001a, FORM-001d.
4. Длины меньше минимума → FORM-001c, FORM-001e; точные сообщения → auth-forms/messages.md.
5. Ошибка клиента без запроса → FORM-001a–FORM-001e; подтверждение регистрации → REG-001b, REG-001c.
6. Неверный пароль, HTTP 401, ошибка формы, отсутствие сессии → AUTH-003a, ACC-001b.
7. Успешный вход и переход на `/` → AUTH-002a.
8. Регистрация на `/register` → REG-001a.
9. HTTP 201, немедленное создание сессии и приветствие → REG-002a, ACC-001a, ACC-003a.
10. Занятое имя, HTTP 409, сообщение, отсутствие сессии → REG-003a, ACC-001b.
11. Выход и очистка токена без серверного отзыва JWT → ACC-004a–ACC-004e.
12. Подтверждённое удаление и очистка сессии → ACC-005b, ACC-006a.
13. Отмена удаления сохраняет сессию → ACC-005a.
14. Сессия после перезагрузки → ACC-002a.
15. Недействительный/истёкший токен, очистка, скрытое приветствие → ACC-002b.
16. Атрибуты полей для идентификации и автозаполнения → FORM-007a и frontend docs/auth-ui.md.

## Детализированные разделы источника

- `pages`, `api`: маршруты сохранены в соответствующих capability и OpenAPI;
  `/api/health` остаётся в HTTP-контракте без выдуманного нового продукта.
- `storage`, `session`: ACC-001–ACC-006; особенности подготовки E2E,
  mock и проверки сети — `docs/qa/auth-checks.md`.
- `formControls`: FORM-007 и точные значения в frontend docs/auth-ui.md,
  включая регистрационную кнопку, ошибку и оба поля поиска header.
- `wrongPassword`: AUTH-003; все ветви fallback — FORM-005;
  демо-фикстура, ссылки на тесты и прежний goldenId — auth-checks.md.
- `bounds`: FORM-001–FORM-003, включая отсутствие клиентского максимума
  и допустимость точных границ.
- `formValidation`: FORM-001, FORM-005, FORM-006 и REG-001;
  18 значений сообщений перенесены дословно в auth-forms/messages.md.
  Реализация переключения языка — frontend docs/auth-ui.md;
  пробел доказательства отсутствия запроса сохранён в auth-checks.md.
- `beanValidation`: FORM-003, FORM-004; сообщения, порядок полей и разделитель
  сохранены; ссылки на проверяющие методы — auth-checks.md.
- `register`: REG-001–REG-003; ограничения mock — auth-checks.md.
- `validLogin`: AUTH-002, ACC-003; имя приветствия берётся из профиля,
  ошибка профиля очищает сессию — ACC-002c.
- `implementation`: существующий docs/coverage-profile.md определяет выбранные
  модули. Упомянутые в исходнике upstream native/React-ячейки не входят в эту сборку.
- `design-system`: frontend docs/auth-ui.md и README модуля; встроенный header,
  vendor/ds и templates сохранены. Исторический upstream PlaqueField был указан
  как `design-system-home/react-ui/PlaqueField.tsx`, но это не локальный модуль.
