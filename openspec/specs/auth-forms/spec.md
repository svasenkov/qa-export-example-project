# Общие правила форм входа и регистрации

## Purpose

Определить общие ограничения учётных данных, порядок клиентских проверок,
локализацию и отображение ошибок. Применяется к [входу](../authentication/spec.md)
и [регистрации](../registration/spec.md). Точные тексты — в [messages.md](messages.md).

## Requirements

### Requirement: FORM-001 Порядок клиентской валидации

Формы SHALL удалять пробелы по краям логина и пароля, затем показывать первую
ошибку в порядке: оба пусты, логин пуст, логин короче 3, пароль пуст, пароль короче 6.
Тексты SHALL соответствовать ключам в [messages.md](messages.md). Ошибка клиента
SHALL блокировать запрос API. Подтверждение регистрации проверяется после этих правил.

#### Scenario: FORM-001a Оба поля пусты

- **WHEN** оба поля после удаления пробелов пусты и форма отправляется
- **THEN** отображается `errorBothRequired`, запрос API не отправляется

#### Scenario: FORM-001b Пустой логин

- **WHEN** логин пуст, пароль непуст и форма отправляется
- **THEN** отображается `errorLoginRequired`, запрос API не отправляется

#### Scenario: FORM-001c Короткий логин

- **WHEN** логин непуст, но короче 3 символов, и форма отправляется
- **THEN** отображается `errorLoginMinLength`, даже если пароль пуст
- **AND** запрос API не отправляется

#### Scenario: FORM-001d Пустой пароль

- **WHEN** логин проходит проверку минимума, пароль пуст и форма отправляется
- **THEN** отображается `errorPasswordRequired`, запрос API не отправляется

#### Scenario: FORM-001e Короткий пароль

- **WHEN** логин проходит проверку минимума, пароль непуст, но короче 6 символов
- **THEN** при отправке отображается `errorPasswordMinLength`, запрос API не отправляется

#### Scenario: FORM-001f Точная минимальная длина

- **WHEN** логин состоит из 3, а пароль из 6 латинских символов
- **THEN** клиентская проверка минимальной длины пропускает эти значения
- **AND** на регистрации дополнительно требуется совпадение подтверждения

### Requirement: FORM-002 Максимальную длину проверяет сервер

Клиент SHALL проверять только минимальную длину. Значения сверх максимума
SHALL доходить до API при прохождении остальных клиентских проверок;
сообщение HTTP 400 показывается в форме дословно. Перенос максимума на клиент
является отдельным изменением требований и не входит в эту спецификацию.

#### Scenario: FORM-002a Превышение максимума

- **WHEN** отправляется логин из 65 или пароль из 129 латинских символов,
  остальные поля и подтверждение допустимы
- **THEN** форма обращается к API и показывает сообщение его HTTP 400

### Requirement: FORM-003 Серверные ограничения учётных данных

API входа и регистрации SHALL принимать длины логина от 3 до 64 и пароля
от 6 до 128 включительно. Пустые или недопустимые по длине поля SHALL давать
HTTP 400 с единственным полем `message`, а не HTTP 401. Ограничения действуют
и при прямом обращении без формы.

#### Scenario: FORM-003a Пустые поля

- **WHEN** API получает пустые логин и пароль
- **THEN** возвращается HTTP 400 с `{"message": "username is required; password is required"}`

#### Scenario: FORM-003b Недопустимая длина

- **WHEN** API получает непустое поле за пределами его диапазона
- **THEN** возвращается HTTP 400 с сообщением `{field} must be {min}-{max} characters`
- **AND** несколько ошибок объединяются через `; ` в порядке логин, пароль

#### Scenario: FORM-003c Допустимые границы

- **WHEN** длины полей равны их минимумам или максимумам
- **THEN** проверка длины их пропускает; дальнейший результат зависит от операции
  и наличия пользователя

### Requirement: FORM-004 Невалидный JSON

API входа и регистрации SHALL возвращать HTTP 400 с телом
`{"message": "Request body is not valid JSON"}` при невозможности декодировать
JSON запроса. Это ошибка запроса, а не отказ аутентификации.

#### Scenario: FORM-004a Повреждённое тело

- **WHEN** клиент отправляет синтаксически невалидный JSON в API входа или регистрации
- **THEN** возвращается HTTP 400 с указанным сообщением

### Requirement: FORM-005 Выбор сообщения ошибки API

Форма SHALL выбирать сообщение в порядке: сетевая ошибка, непустое сообщение,
локализованный fallback. Строка API `message` SHALL показываться дословно на любом
языке. Пустая строка использует fallback входа или регистрации; отсутствующее
или нестроковое `message` SHALL отображаться как `Request failed`.

#### Scenario: FORM-005a Сеть недоступна

- **WHEN** запрос завершается сетевой ошибкой
- **THEN** отображается `errorNetwork` на выбранном языке

#### Scenario: FORM-005b Непустое сообщение API

- **WHEN** API возвращает непустую строку `message`
- **THEN** форма показывает её дословно, в том числе при русском интерфейсе

#### Scenario: FORM-005c Пустая строка сообщения

- **WHEN** API возвращает `message: ""`
- **THEN** вход показывает `errorWrongCredentials`, а регистрация — `errorRegistrationFailed`

#### Scenario: FORM-005d Отсутствующее или нестроковое сообщение

- **WHEN** в ответе отсутствует `message` либо его значение не является строкой
- **THEN** форма показывает `Request failed`, а не локализованный fallback

### Requirement: FORM-006 Локализация и область ошибки

Формы SHALL использовать язык en или ru из localStorage `zds-lang`, по умолчанию en.
Локальные ошибки SHALL соответствовать [messages.md](messages.md).
Форма SHALL показывать одну ошибку в элементе `p` с `aria-live="polite"`:
`#error-message` для входа и `#register-error-message` для регистрации.

#### Scenario: FORM-006a Язык по умолчанию

- **WHEN** форма открывается без сохранённого языка и возникает локальная ошибка
- **THEN** она показывается на английском в области ошибки соответствующей формы

#### Scenario: FORM-006b Русский язык

- **WHEN** форма открывается с `zds-lang=ru` и возникает локальная ошибка
- **THEN** она показывается на русском с точным текстом из messages.md

### Requirement: FORM-007 Идентификация элементов форм

Элементы `input`, `select` и `textarea` SHALL иметь `id` или `name`, предпочтительно
оба. Поля входа и регистрации SHALL сохранять оба атрибута и значения autocomplete,
описанные в [UI-соглашениях](../../../frontend/typescript/frontend-typescript-vue/docs/auth-ui.md).

#### Scenario: FORM-007a Поля аутентификации

- **WHEN** отображаются формы входа и регистрации
- **THEN** их поля имеют предусмотренные `id`, `name` и autocomplete
- **AND** `name` отражает назначение поля для автозаполнения, а не копирует testid
