# Вход пользователя

## Purpose

Определить доступ к форме входа, успешную аутентификацию и отказ при неверных
учётных данных. HTTP-структуры описаны в [OpenAPI](../../../docs/api/openapi.yaml),
общая валидация — в [auth-forms](../auth-forms/spec.md).

## Requirements

### Requirement: AUTH-001 Доступ к форме входа

Приложение SHALL предоставлять форму входа на `/login`. При наличии сохранённого
токена открытие этой страницы SHALL перенаправлять на `/` с заменой записи истории;
пригодность токена проверяется на главной странице согласно [account](../account/spec.md).

#### Scenario: AUTH-001a Открытие без сессии

- **WHEN** пользователь без сохранённого токена открывает `/login`
- **THEN** отображается форма с полями логина и пароля

#### Scenario: AUTH-001b Открытие с сохранённым токеном

- **WHEN** пользователь с сохранённым токеном открывает `/login`
- **THEN** приложение перенаправляет на `/` с заменой записи истории
- **AND** наличие токена само по себе не подтверждает его действительность

### Requirement: AUTH-002 Успешный вход

Система SHALL принимать действительные учётные данные через `POST /api/auth/login`,
возвращать HTTP 200 с `AuthResponse` и `redirectUrl: "/"`. Форма SHALL сохранять
полученный токен только после успешного ответа и переходить на `redirectUrl` либо `/`,
если значение отсутствует или пусто. Приветствие определяется ответом профиля.

#### Scenario: AUTH-002a Вход существующего пользователя

- **WHEN** пользователь отправляет правильные логин и пароль
- **THEN** API возвращает HTTP 200 с токеном и именем пользователя
- **AND** форма сохраняет токен и переходит на главную страницу
- **AND** главная страница получает профиль через `GET /api/auth/me`

#### Scenario: AUTH-002b Учётные данные на минимальной границе

- **GIVEN** существует пользователь с логином из 3 и паролем из 6 латинских символов
- **WHEN** он отправляет эти данные через форму входа
- **THEN** минимальная длина не блокирует вход

### Requirement: AUTH-003 Отказ при неверных учётных данных

API SHALL одинаково отклонять неверный пароль известного пользователя и неизвестное
имя: HTTP 401 с телом `{"message": "Wrong login or password"}` без дополнительных
полей. Форма SHALL показывать сообщение дословно на любом языке интерфейса,
оставаться на `/login` и не создавать сессию.

#### Scenario: AUTH-003a Неверный пароль известного пользователя

- **GIVEN** сессия отсутствует, пользователь существует, длины полей допустимы
- **WHEN** пользователь отправляет неверный пароль
- **THEN** API возвращает HTTP 401 с указанным сообщением
- **AND** форма показывает его без перенаправления и без сохранения токена

#### Scenario: AUTH-003b Неизвестное имя

- **WHEN** отправлены неизвестное имя и пароль допустимой длины
- **THEN** API возвращает тот же HTTP 401 и то же тело, что при неверном пароле
