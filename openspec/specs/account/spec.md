# Учётная запись и сессия

## Purpose

Определить хранение и восстановление сессии, получение профиля, выход и удаление
учётной записи. Контракты HTTP доступны в [OpenAPI](../../../docs/api/openapi.yaml).

## Requirements

### Requirement: ACC-001 Хранение и транспорт сессии

Клиент SHALL хранить токен в localStorage под `authToken`, а под matrix mount —
`authToken:<backendId>`. Запросы профиля и удаления SHALL передавать Bearer JWT
в `Authorization`. Сессия не является cookie-сессией; удаление cookies не завершает её.
Токен SHALL записываться только после успешного входа или регистрации, не после 4xx.

#### Scenario: ACC-001a Создание сессии

- **WHEN** приходит успешный ответ входа или регистрации с токеном
- **THEN** токен записывается в соответствующий ключ localStorage после ответа
- **AND** защищённые запросы используют `Authorization: Bearer <token>`

#### Scenario: ACC-001b Ошибка аутентификации

- **GIVEN** до запроса сохранённого токена не было
- **WHEN** API возвращает 4xx на вход или регистрацию
- **THEN** токен не появляется в localStorage

### Requirement: ACC-002 Восстановление и срок сессии

Сессия SHALL переживать перезагрузку страницы: главная страница читает сохранённый
токен и запрашивает профиль. JWT SHALL иметь срок `exp`, по умолчанию 86400000 мс
(24 часа), настраиваемый через `JWT_EXPIRATION_MS`. Ошибка получения профиля
SHALL очищать локальную сессию и оставлять приветствие скрытым.

#### Scenario: ACC-002a Перезагрузка страницы

- **WHEN** пользователь с действительным токеном перезагружает главную страницу
- **THEN** токен сохраняется и профиль повторно загружается
- **AND** приветствие отображается после успешного ответа профиля

#### Scenario: ACC-002b Недействительный или истёкший токен

- **WHEN** главная страница получает отказ профиля для такого токена
- **THEN** локальный токен удаляется, приветствие остаётся скрытым

#### Scenario: ACC-002c Другая ошибка профиля

- **WHEN** запрос профиля на главной странице завершается ошибкой
- **THEN** локальная сессия очищается и приветствие не показывается

### Requirement: ACC-003 Приветствие по профилю

Главная страница SHALL показывать приветствие только после успешного
`GET /api/auth/me`, используя имя из этого ответа, а не из ответа входа:
`Welcome, {username}!` для en и `Добро пожаловать, {username}!` для ru.

#### Scenario: ACC-003a Получен профиль

- **WHEN** запрос профиля возвращает HTTP 200 с именем пользователя
- **THEN** панель приветствия видима и содержит имя из профиля на выбранном языке

### Requirement: ACC-004 Выход из приложения

`POST /api/auth/logout` SHALL возвращать HTTP 204 с пустым телом без обязательной
аутентификации. Клиент SHALL ждать завершения запроса, затем удалять локальный
токен и переходить на `/login`, даже при ошибке запроса. Выход не отзывает JWT
на сервере: он остаётся действительным до `exp`, если учётная запись существует.

#### Scenario: ACC-004a Успешный выход

- **WHEN** пользователь нажимает выход и запрос завершается
- **THEN** локальный токен удаляется и открывается `/login`

#### Scenario: ACC-004b Ошибка запроса выхода

- **WHEN** запрос выхода отклонён или завершается ошибкой
- **THEN** локальный токен всё равно удаляется и открывается `/login`

#### Scenario: ACC-004c Запрос выхода не завершается

- **WHEN** запрос выхода остаётся в ожидании
- **THEN** удаление токена и переход также ожидают завершения запроса

#### Scenario: ACC-004d Токен после выхода

- **GIVEN** JWT ещё не истёк и учётная запись существует
- **WHEN** после выхода клиент повторно обращается к профилю с тем же JWT
- **THEN** API возвращает HTTP 200

#### Scenario: ACC-004e Выход без токена

- **WHEN** клиент вызывает `POST /api/auth/logout` без аутентификации
- **THEN** API возвращает HTTP 204 с пустым телом

### Requirement: ACC-005 Подтверждение удаления учётной записи

Клиент SHALL запрашивать подтверждение перед удалением учётной записи.
Отмена SHALL сохранять сессию и не отправлять `DELETE /api/auth/me`.
После подтверждения клиент SHALL дождаться завершения запроса удаления,
очистить локальный токен даже при ошибке запроса и перейти на `/login`.

#### Scenario: ACC-005a Отмена

- **WHEN** пользователь отменяет подтверждение удаления
- **THEN** запрос удаления не отправляется, токен и приветствие сохраняются

#### Scenario: ACC-005b Подтверждение

- **WHEN** пользователь подтверждает удаление и запрос завершается успешно
- **THEN** токен удаляется и открывается `/login`

#### Scenario: ACC-005c Ошибка удаления

- **WHEN** подтверждённый запрос удаления завершается ошибкой
- **THEN** клиент всё равно удаляет токен и переходит на `/login`

### Requirement: ACC-006 Серверное удаление учётной записи

API SHALL удалять текущую учётную запись по `DELETE /api/auth/me` с действительным
Bearer JWT и возвращать HTTP 204. Отсутствующий или недействительный токен
SHALL давать HTTP 401. После удаления тот же JWT SHALL получать HTTP 401
на чтение профиля и повторное удаление, даже если его подпись и срок ещё допустимы.

#### Scenario: ACC-006a Удалённая учётная запись

- **WHEN** учётная запись удалена через API
- **THEN** повторные GET и DELETE `/api/auth/me` с прежним JWT возвращают HTTP 401

#### Scenario: ACC-006b Нет действительного токена

- **WHEN** DELETE `/api/auth/me` вызван без токена или с недействительным токеном
- **THEN** API возвращает HTTP 401
