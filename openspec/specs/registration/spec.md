# Регистрация

## Purpose

Определить создание учётной записи через форму регистрации, подтверждение пароля
и отказ при занятом имени. Общие ограничения полей и ошибки определяет
[auth-forms](../auth-forms/spec.md), HTTP-структуры — [OpenAPI](../../../docs/api/openapi.yaml).

## Requirements

### Requirement: REG-001 Форма и подтверждение пароля

Приложение SHALL предоставлять `/register` с логином, паролем и подтверждением.
Форма SHALL удалять пробелы по краям подтверждения и проверять его совпадение
с обработанным паролем после общих проверок логина и пароля. При несовпадении
SHALL показываться `errorPasswordMismatch` из [сообщений](../auth-forms/messages.md)
без запроса регистрации.

#### Scenario: REG-001a Открытие регистрации

- **WHEN** пользователь открывает `/register`
- **THEN** доступны логин, пароль, подтверждение и отправка формы

#### Scenario: REG-001b Пароли не совпадают

- **GIVEN** логин и пароль проходят общие клиентские проверки
- **WHEN** пользователь отправляет отличающееся подтверждение
- **THEN** отображается ошибка несовпадения
- **AND** `POST /api/auth/register` не отправляется

#### Scenario: REG-001c Подтверждение пустое или из пробелов

- **GIVEN** логин и пароль проходят общие клиентские проверки
- **WHEN** подтверждение пустое или содержит только пробелы
- **THEN** отображается `errorPasswordMismatch`, а запрос не отправляется

### Requirement: REG-002 Регистрация создаёт сессию

Система SHALL создавать нового пользователя через `POST /api/auth/register`
и возвращать HTTP 201 с `AuthResponse` и `redirectUrl: "/"`. Форма SHALL сохранять
токен после ответа и переходить на `redirectUrl` либо `/`, если значение отсутствует
или пусто. Повторный вход после регистрации не требуется.

#### Scenario: REG-002a Новый пользователь

- **WHEN** пользователь отправляет свободное имя и допустимые совпадающие пароли
- **THEN** API возвращает HTTP 201 с токеном
- **AND** форма сохраняет сессию и переходит на главную страницу
- **AND** приветствие загружается через `GET /api/auth/me`

#### Scenario: REG-002b Минимальные длины

- **WHEN** отправлены свободное имя из 3 латинских символов и совпадающие пароли из 6
- **THEN** длины считаются допустимыми, регистрация завершается HTTP 201

### Requirement: REG-003 Занятое имя

API SHALL отклонять регистрацию существующего имени с HTTP 409 и телом
`{"message": "Username already taken"}` без дополнительных полей, включая
конкурирующее создание одного имени. Форма SHALL показывать сообщение дословно
на любом языке, оставаться на `/register` и не сохранять новый токен.

#### Scenario: REG-003a Повторная регистрация

- **GIVEN** сессия отсутствует, имя уже занято
- **WHEN** пользователь отправляет допустимые данные регистрации с этим именем
- **THEN** API возвращает HTTP 409 с указанным сообщением
- **AND** форма показывает ошибку, остаётся на `/register`, сессия не создаётся
