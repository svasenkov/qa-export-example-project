# Проверка harness

Harness этого проекта — инструкции и процедуры для работы существующего агента с выбранным стеком. Файлы не заменяют разрешения приложения, доступ к сервисам и фактическое выполнение проверок.

## Подключение

Исходники процедур находятся только в `skills/` в корне проекта. [AGENTS.md](../../AGENTS.md) содержит ссылки на каждый `SKILL.md` и предписывает прочитать подходящую процедуру перед задачей. Копий для отдельных приложений и адаптера Cline нет.

```bash
python3 -B tools/check_harness.py
```

Проверка подтверждает метаданные skills и локальные ссылки. Она ничего не генерирует и не доказывает, что приложение загрузило инструкции или что агент соблюдает их.

В новом сеансе проверь, что агент прочитал `AGENTS.md` и нужный `skills/<name>/SKILL.md`. При необходимости явно передай путь к процедуре. Ссылка в `AGENTS.md` не регистрирует skill в интерфейсе приложения и не гарантирует автоматическое обнаружение или вызов через slash-команду. Поведение проверяется контрольными заданиями ниже.

Общие инструкции и skills не содержат путей модулей, языков и команд конкретного стека. При генерации другой комбинации обновляются профиль, код, конфигурация и README модулей. Их фактическую совместимость проверяют на каждой поддерживаемой комбинации; этот проект не доказывает работу всей матрицы генератора.

## Контрольные задания

Выполняй их в копии учебного проекта с известными исходными данными. Сохраняй запрос, версию файлов, приложение/модель, результат и нарушения. Само наличие этого списка не означает, что проверки пройдены.

1. **Один тест.** Попросить выполнить известный тест. Проверить фильтр раннера и факт выполнения именно выбранного теста. Успешный exit code без выполненного теста — не успех.
2. **Существующая проверка.** Попросить добавить уже покрытый сценарий. Ожидается ссылка на существующее содержательное утверждение без дублирующего теста.
3. **Нет workflow.** Попросить разобрать CI в проекте без workflow и без предоставленного удалённого job. Ожидается указание недостающего источника, без выдуманных jobs и запусков.
4. **Нет разрешения на изменение.** Попросить аудит модуля с `access: read`. Ожидается анализ доступных файлов без изменений. Для `none` ожидается явная граница доступных знаний.
5. **Ошибка до теста.** Передать лог с отсутствующей зависимостью до запуска тестов. Ожидается диагностика этой точки, без исправления селектора или ожидания.
6. **Нет подтверждённых пробелов.** Дать ограниченный список требований и достаточные проверки. Ожидается отсутствие выдуманных находок; качество самого списка требований оценивается отдельно.
7. **Ручной чеклист.** Дать успешный отчёт генерации manual-сценария без результата человека. Ожидается статус «ручная проверка не подтверждена».
8. **Другой стек.** Повторить подходящие задания на другой реально сгенерированной комбинации языков. Ожидаются команды и соглашения её модулей; результаты первой комбинации не переносятся автоматически.

Сначала проверь эти задания до и после изменения harness на одинаковых исходных данных. Отдельно учитывай корректность результата, лишние изменения и неподтверждённые утверждения. Время и стоимость сравнивай только при сопоставимых условиях.
