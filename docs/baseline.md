# Исходное состояние дипломного проекта

Проверено 16 октября 2026 года в текущей сборке Go + Vue/TypeScript + Java. Это результат проверки исходного приложения, а не готовность дипломной версии. Коду продукта и автотестам в этой задаче изменений не внесено.

## Выполнено

- Backend без внешней БД: 58 тестов верхнего уровня прошли. JSON Go содержит 151 событие `pass` с именем теста, включая вложенные subtests; эти числа нельзя складывать. Три PostgreSQL integration-теста в этом запуске пропущены.
- Integration отдельно: `TestPostgresItems`, `TestPostgresUsers`, `TestPostgresSeedIsIdempotent` прошли на новой одноразовой БД PostgreSQL. Созданный контейнер затем остановлен и автоматически удалён. Другие локальные базы не использовались.
- Frontend component: 83 проверки прошли, пропусков и падений нет.
- Frontend: проверка типов и production-сборка завершились с exit code 0.
- Harness: 7 unit-тестов инструмента синхронизации прошли; проверка metadata, локальных ссылок harness и совпадения адаптеров прошла.
- Compose: `docker compose -p qa-diploma --env-file .env.diploma.example config --quiet` прошёл. Это проверка конфигурации; приложение через этот новый Compose-проект пока не запускалось.

Java API/UI/E2E, CI, ручные проверки и поведение skills в отдельной сессии агента в этом запуске не проверялись. Процент покрытия требований не вычислялся: перечень требований полной версии ещё не утверждён.

## Команды и среда

Go: `go1.27.0`; frontend проверялся с Node `v24.18.0`. Зависимости frontend установлены через `npm ci` по существующему lock-файлу.

Из backend-модуля:

```bash
env -u TEST_DATABASE_URL GOCACHE=/tmp/qa-diploma-go-build \
  go test -count=1 -json ./...

# TEST_DATABASE_URL задавался для созданной временной scratch-БД.
GOCACHE=/tmp/qa-diploma-go-build \
  go test -count=1 -json ./internal/store -run '^TestPostgres'
```

Вторая команда требует явно переданного `TEST_DATABASE_URL`; иначе тесты пропускаются. Подготовка отдельной БД описана в [README backend](../backend/go/backend-go-stdlib/README.md).

Из frontend-модуля, с Node 24.18.0 первым в PATH:

```bash
npm test -- --reporter=json --outputFile=/tmp/qa-diploma-vue-baseline-20261016.json
npm run typecheck
npm run build
```

Отчёт baseline записан JSON-репортёром. Генерация Allure этим запуском не подтверждена.

Из корня:

```bash
python3 tools/sync_adapters.py --check
python3 -B -m unittest discover -s tools -p 'test_*.py'
docker compose -p qa-diploma --env-file .env.diploma.example config --quiet
```

## Препятствия и устранение

Первый Go-запуск завершился неуспешно из-за запрета записи части кеша вне workspace. Повторный запуск использовал отдельный `GOCACHE` и прошёл. Это разные попытки; первый результат не считается успешным.

Первый frontend-запуск не нашёл `vitest`: зависимости ещё не были установлены. Первая попытка `npm ci` получила `ENOTFOUND` для npm registry в ограниченной сети и завершилась ошибкой npm. Установка повторена с разрешённым сетевым доступом и явным Node 24.18.0, после чего проверки выполнены успешно. Lock-файл не обновлялся намеренно.

Docker первоначально был недоступен из sandbox. После разрешённого read-only обращения обнаружены контейнеры другой сборки с именем `autotests-ai-multistack-app` и занятыми портами по умолчанию. Они не пересоздавались. Для дальнейшей работы добавлен отдельный локальный профиль портов в [.env.diploma.example](../.env.diploma.example) и инструкция в [README](../README.md).

## Артефакты

При очистке проекта 17 октября 2026 года прежние результаты вынесены из рабочего дерева в архив `qa-project-archive-20261017-140953/before-cleanup.tar.gz` рядом с проектом. Внутри сохранён путь `build/diploma-baseline-2026-10-16/` с файлами `go-unit.jsonl`, `go-integration.jsonl`, `vue-component.json`, `vue-build.log`, `manifest.json`, а также последующие Java-результаты в `build/diploma-fix-2026-10-17/`. Архив проверен по SHA-256 перед удалением рабочих копий. Результаты исторические и не подтверждают состояние после последующих изменений.

В manifest записаны SHA-256 отчётов и 321 файла исходного дерева модулей/контрактов, исключая зависимости и результаты сборки. Хеши сняты после запусков; код продукта и тесты между запуском и снимком не менялись. Git revision отсутствует. Exit codes команд без отдельного журнала зафиксированы по результатам инструментов этой сессии.

## Что требует отдельной работы

В документации Java-модуля отмечены ограничения исходного кода: `deleteAccountQuietly` подавляет ошибки очистки; наличие `@Step` без пароля в заголовке не подтверждает отсутствие секрета в параметрах и HTTP-вложениях. Эти свойства не исправлены и не выдаются за безопасную публикацию отчётов.

Frontend при удалении аккаунта сейчас очищает сессию даже при неудаче запроса; такое поведение описано в его исходном README. Для полной версии необходимо сначала определить пользовательский результат ошибки удаления, затем согласованно менять реализацию, контракт и проверки.

Следующая зависимость — выбор предметной области и конкретных требований из [дипломного проекта](diploma.md). Каталог с коллекциями пока является предложением.
